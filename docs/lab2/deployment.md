# Публикация сайта

**Статус:** workflow подготовлен локально. Реальные запуски и публикация ещё не проверены.

## События и результат

| Событие | Поведение |
| --- | --- |
| Push в ветку, включая lab2 и master | Ruff, mypy, pytest и строгая сборка; без публикации |
| Pull request | Те же проверки; без доступа к токену SourceCraft |
| Push тега v1.0 или v1.1 | Проверки, сборка всех доступных поддерживаемых версий и деплой на две площадки |

Тег выпуска должен указывать на коммит, входящий в `origin/master`.
Тег `lab1` не запускает публикацию. Нельзя переносить уже опубликованные теги.

`build` собирает два дерева сайта с разными `site_url`. `deploy-pages` и
`deploy-sourcecraft` зависят от успешного `build`, но независимы друг от друга.
При сбое одной площадки другая может уже обновиться; нужно проверить оба job.

## Сохранение версий

В каждом запуске страницы берутся из снимков `docs/` и `mkdocs.yml` тегов
`v1.0` и `v1.1`. Отдельный временный Git-репозиторий и mike формируют всё дерево
версий; `latest` назначается самой новой поддерживаемой версии.
В GitHub не отправляется служебная ветка `gh-pages`: дерево загружается через
`upload-pages-artifact` и публикуется `deploy-pages`.

Старые версии пересобираются текущим зафиксированным окружением workflow:
содержание берётся из старого тега, но побайтовая идентичность старого HTML
не гарантируется при обновлении темы или генератора.

Исходные XLSX в CI не требуются: таблица и график хранятся в каждом теге.
Перед выпуском v1.1 нужно отдельно обновить результаты и описание периода,
проверить их и включить в коммит. Сам тег не добавляет данные за 2021 год.

## Подготовка аккаунтов

1. GitHub: Settings → Pages → Source → GitHub Actions.
2. В Settings → Environments → github-pages проверьте правила развёртывания:
   они должны разрешать теги `v1.0` и `v1.1`. Правило только для ветки master
   не разрешает запуск, инициированный тегом.
3. SourceCraft: публичная организация `kholodkova-research-global-health`
   и публичный репозиторий `research-global-health`.
4. GitHub Actions repository secret: `SOURCECRAFT_TOKEN`, право записи только
   в этот репозиторий SourceCraft. Токен не хранится в Git или URL remote.

SourceCraft-репозиторий предназначен для собранного сайта. Workflow заменяет
его содержимое (с сохранением истории Git) и пишет `.sourcecraft/sites.yaml`
в основную ветку. Не размещайте там самостоятельные исходники или ручные правки.

## Выпуск после согласования

Сначала изменения должны пройти проверки и попасть в master. Затем для каждого
выпуска отдельно создаётся и отправляется конкретный тег, например:

```bash
git tag v1.0
git push origin v1.0
```

Эти команды запускают внешнюю публикацию; выполняются только после согласования.
Для v1.1 процедура повторяется после подготовки новых результатов.

## Проверка

`scripts/healthcheck.sh` проверяет HTTP 200, наличие DALY на странице результатов,
список версий и точное совпадение версии и SHA в `release.json`.
Повторные попытки учитывают задержку обновления хостинга. Ошибка проверки
завершает job с ошибкой, но автоматически не откатывает уже опубликованный сайт.

После первого деплоя дополнительно проверяются переключатель, графики, latest,
поиск и работа в подкаталоге в браузере. Скриншоты и замеры реальных запусков
будут добавлены в отчёт после публикации.
